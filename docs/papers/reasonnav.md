# ReasonNav: Human-like Navigation in a World Built for Humans (arXiv 2509.21189v1, UIUC, CoRL 2025)

본문 8쪽 + 부록 포함 19쪽 전문 정독. 프로젝트 페이지 reasonnav.github.io. 시뮬 환경·코드 공개는 "예정"이라고만 적혀 있다.

## 논문 내용

**과제**: 처음 보는 큰 건물에서 **방 번호로 지정된 목표 방 1개**를 찾는다(배달 시나리오). 목표 방 문패를 VLM이 읽으면 성공, 제한 15분.
사람처럼 **표지판 읽기, 문패 읽기와 번호 패턴 따라가기, 사람에게 길 묻기**를 VLM 에이전트로 통합한다.

### 구조

| 층 | 내용 |
|---|---|
| 저수준 | SLAM Toolbox(3D 라이다를 2D 스캔으로 합쳐 점유 지도), NanoOWL(OWL-ViT) 개방 어휘 검출 "door / person / directions sign", NavFn(Dijkstra) + MPPI |
| 기억(landmark memory bank) | 문(→ 문패 텍스트), 사람(→ VLM이 쓴 대화 요약 노트), 표지판(→ 8방위별 텍스트), **프런티어**(VLFM 방식: 탐사/미탐사 경계 선분 중점). 각 항목에 index와 Visited/Unvisited |
| VLM 입력 | 기억의 JSON + **상단뷰 지도 이미지**(점유·탐사 영역 색, 랜드마크 기호와 번호, 북쪽 위, 테두리에 N/S/E/W) |
| VLM 출력 | **다음에 갈 랜드마크 번호 하나**(좌표를 내지 않음) + 추론 문장 |
| 행동 원형 | 프런티어: 이동 후 360° 회전 / 문: 접근, 카메라 팬, 문패 검출 시 근접해 VLM으로 판독 / 사람: TTS로 질문, STT로 답 기록, VLM이 노트 작성 / 표지판: VLM 판독, 화살표를 방위로 묶어 전역 좌표로 변환 |
| VLM | GPT-4.1 (API, 인터넷 연결) |

### 언어를 플래너가 쓰는 방식

- 사람 답변("왼쪽이에요", "뒤쪽 두 번째 문")은 VLM이 **로봇이 바라보는 방위를 받아 전역 방위 문장으로 바꾼 노트**로 저장한다. 예: "북쪽을 보고 있으니 오른쪽은 동쪽. 4124는 왼쪽으로 돌아 복도를 따라 서쪽." 나중에 자세 없이도 해석되게 하려는 것.
- 사람 방향은 **로봇 기준**이라고 가정한다(D.5). 화자 기준 방향은 다루지 않는다.
- 노트·표지판 방위·문패 번호는 **텍스트 그대로** JSON에 들어가고, 다음 랜드마크 선택은 VLM 추론이 전부다. 프롬프트: "표지판·사람 정보는 그 랜드마크 근처에서만 유효할 것", "방향 정보가 있으면 근처 탐색보다 우선", "오름차순 패턴이면 중간 번호 건너뛰기", "방문한 랜드마크 금지".
- 수치화된 확률 지도, 거리 해석, 점수 함수는 없다.

### 믿음·불확실성

- 명시적 확률 믿음 없음. Visited 표시와 텍스트 노트가 전부다.
- 문패 판독 프롬프트는 신뢰도(0–1)를 내게 하지만 이것을 계획에 어떻게 쓰는지는 적혀 있지 않다.
- 답이 불명확하면 "얻은 정보 없음"으로 기록. **어느 사람이 더 잘 아는지는 추론하지 않는다**고 명시. 시뮬 NPC는 의사/간호사/환자별로 아는 범위가 다르고 모르면 "모른다"고 답한다(틀린 답을 하는 NPC는 없음).

### 실험

| 항목 | 실물 | 시뮬 |
|---|---|---|
| 환경 | 대학 건물 A, B(각 80 m 이상), 문패·표지판·사람 | Isaac Sim 병원, 30개 이상 방(3001–3041), 표지판 4개, NPC 11명 |
| 시행 | A 10회 + B 2회 = 12회, 사람 배우 1–2명 고정 위치 | 14회 |
| 로봇 | AgileX Ranger Mini 2.0(바퀴) + xArm7(미사용) + 2D·3D 라이다(Hesai FT120) + 팬틸트 D455, RTX 4070 노트북, 약 3.5만 달러 | 같은 ROS 2 인터페이스 |
| 기준선 | 표지판·사람 없음(프런티어와 문만), 지도 이미지 없음(JSON만) | + VLM 없이 가장 가까운/무작위 미방문 랜드마크, JSON 없음 |
| 지표 | 성공률, 평균 시간, 이동 거리(실패는 900 s, 100 m로 처리) | 같음 |

### 주요 결과

실물(표 1):

| 방법 | 성공 A | 성공 B | 시간 A (s) | 시간 B (s) | 거리 A (m) | 거리 B (m) | 평균 성공 (%) |
|---|---|---|---|---|---|---|---|
| 표지판·사람 없음 | 10 | 0 | 817.00 | 900 | 90.48 | 100 | 8.3 |
| 지도 이미지 없음 | 20 | 0 | 679.72 | 900 | 73.52 | 100 | 16.6 |
| ReasonNav | 50 | 100 | 572.35 | 232.63 | 60.28 | 12.61 | 58.3 |

시뮬(표 2, 4): 성공률 ReasonNav 57.14 %(609.0 s, 72.5 m), 표지판·사람 없음 42.86 %(710.8 s), 지도 이미지 없음 14.29 %, 가장 가까운 랜드마크 35.71 %, 무작위 28.57 %, JSON 없음 0 %.

- 실물 B는 2회뿐이라 100 %의 통계적 의미는 작다. 실물 평균 58.3 %는 7/12.
- 실패 원인(상위 3개 누적, 표 3): 실물 오검출 33.33 %, 미검출 26.67 %, 추론 실패 20.00 %, **사람의 틀린 정보 13.33 %**, SLAM 6.67 % / 시뮬 저수준 플래너 28.57 %, 오검출·미검출 각 21.43 %, SLAM 14.29 %, 추론 7.14 %.
- 부록 F: 엘리베이터로 층 이동 시연(팔로 버튼 누름, 층 바뀌면 SLAM·랜드마크 지도 초기화). 정량 결과 없음.

## 논문에 없는 것

- **여러 목표**, 개수 정보, 사람(피해자) 탐색. 목표는 문패가 있는 정적인 방 하나다.
- **확률 표현**: 단서의 공간 분포, 미탐지 갱신, 시간 경과 확산 없음. 거리("20 m쯤") 해석 없음.
- **틀린 단서**를 실험 변수로 다루지 않는다. 실물에서 틀린 정보가 실패 원인의 13.33 %로 나왔다는 관찰만 있다. 오래된 단서도 없음.
- **움직이는 사람**: 질문할 사람이 걸어가 버리면 정보가 없을 뿐이고 동적 행위자는 향후 과제(D.5).
- 화자 기준 방향(화자의 자세·위치 추정) 없음. 사람의 위치 자체가 랜드마크라 "그 사람 근처에서만 유효"로 처리.
- mapped ≠ searched: 카메라는 검출·문자 판독만 하고 지도는 라이다로 만든다는 점은 우리와 같지만, "카메라가 본 곳"을 따로 관리하지 않는다. 프런티어 도착 후 360° 회전으로 대신한다.
- 학습형 가중치 없음(영점 GPT-4.1). 다리 로봇 아님. 시행 수가 작다(12, 14).

## 우리 설계에 주는 영향

1. **가장 가까운 겹침은 "방 번호/순번 단서 + 문패 읽기"다.** 우리는 방 단서를 "문패가 나오기 전엔 복도상 기대 위치, 나온 뒤엔 해당 방"으로 바꾼다. ReasonNav는 같은 정보를 VLM 텍스트 추론(번호 오름차순 건너뛰기)으로 처리한다. 즉 "문패·순번으로 방을 특정한다"는 아이디어 자체는 이미 있다. 우리 차별점은 이것을 **확률 질량으로 표현해 기대 피해자/시간 점수에 넣고**, 틀림·노화·여러 단서 결합을 코드로 다룬다는 점이다.
2. **방향 정규화 방식은 가져다 쓴다.** 상대 방향("왼쪽")을 받을 때의 방위로 즉시 전역 방향으로 바꿔 저장하는 것은 우리 direction_deg 변환과 같은 생각이다. 다만 ReasonNav는 "로봇 기준"만 가정한다. 우리 "제 오른쪽"은 **화자 기준**이므로 화자 방향(로봇을 마주 본다고 가정하면 180° 반전 등)을 명시해야 하고, 이것이 우리 쪽 추가 문제다.
3. **실패 원인 13.33 %가 사람의 틀린 정보**라는 실측은 우리 "1/3 틀린 단서면 이득이 사라진다" 실험의 동기로 인용할 수 있다. 우리는 신뢰도 혼합(trust × 단서 질량)과 미탐지 갱신으로 이 문제를 정량적으로 다룬다는 점을 내세운다.
4. **기준선**: "VLM이 랜드마크(프런티어·문)를 하나 고른다" 방식을 Qwen3-VL-8B로 재현해 비교할 수 있다. 그들의 절제 기준선 "가장 가까운 미방문 랜드마크"(35.71 %)는 우리 "가장 가까운 프런티어" 기준선과 같다.
5. **평가 지표**: 성공률 + 시간 + 거리, 실패에 상한값 부여 방식은 실물 시험 보고에 그대로 쓸 수 있다. 실패 원인 상위 3개 누적 표도 실물 단계에서 따라 할 만하다.
6. **지도 이미지 입력의 중요성**(없으면 실물 16.6 %, 시뮬 14.29 %)은, 만약 우리가 VLM을 번역 외 용도로 쓸 때 참고. 우리 VLM은 지도를 보지 않으므로 해당 없음.
7. ReasonNav는 바퀴 로봇 + 3.5만 달러 장비, 인터넷 API 의존. 우리는 Go2 + 로컬 8B라 오프라인 재난 현장에 맞는다는 실용적 차이를 적을 수 있다(기여의 핵심은 아님).
