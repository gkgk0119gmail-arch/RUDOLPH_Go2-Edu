# COMRES-VLM (구 LLM-MCoX): VLM 기반 다중 로봇 탐사·탐색 (arXiv 2509.26324v3, Duke, 2026-03)

v3 8쪽 전문 정독, v1(LLM-MCoX, 2025-09) 8쪽도 정독해 차이를 적었다. 게재처는 논문에 적혀 있지 않다(arXiv 프리프린트). 코드 공개 언급 없음.

## 논문 내용

**과제**: 미지의 2D 실내 격자 지도에서 M대 로봇이 (a) 탐사(관측 가능 영역의 95 % 관측) 또는 (b) 미지 위치의 **물체 1개** 탐색(그 셀이 관측되면 성공)을 한다.
중앙 서버의 VLM(GPT-4o)이 T_H 스텝마다 모든 로봇의 웨이포인트 열을 한 번에 출력한다.

### 입력·출력

| 항목 | 내용 |
|---|---|
| 지도 | 각 로봇 지역 지도를 합친 전역 점유 격자 G (unknown / free / occupied). 회색조 이미지(base64)로 VLM에 전달 |
| 구조 정보 | 프런티어 클러스터(4-이웃 프런티어 셀을 free 연결 BFS로 묶음, 최대 측지 거리 c_max로 제한, 중심에 가장 가까운 셀이 대표점, 크기 포함). Zhang–Suen 세선화로 얻은 free 공간 **위상 골격**을 이미지에 겹침 |
| 로봇 상태 | 각 로봇 (row, col) 위치를 텍스트로 |
| 언어 | 선택 입력 "Key Initial Information". 예: "목표는 아래쪽 방들, 특히 복도 끝 쪽에 있을 것" |
| 출력 | JSON `{"Assignments": {"1": [{"position": [y,x]}, ...], ...}}` — 로봇별 웨이포인트 목록 |
| 안전장치 | JSON 실패 시 최대 3회 재질의, 도달 불가 웨이포인트는 지역 제어기가 기각, 웨이포인트가 다 떨어지면 가장 가까운 프런티어로 감(탐욕). 재질의·대체는 전체 실행의 1 % 미만 |

### 언어를 플래너가 쓰는 방식

- 언어는 **프롬프트 문장으로만** 들어간다. 확률 지도, 영역 마스크, 점수 함수로 바뀌지 않는다. "prior is converted into spatial guidance and incorporated into the high-level planning prompt"라고만 적혀 있고, 그 변환이 무엇인지는 그림 3의 프롬프트(문장을 그대로 넣음) 외에 설명이 없다.
- 프롬프트 지시: "사전 정보가 있으면 그 영역을 우선하고 지도와 추측으로 웨이포인트를 배정하라", "로봇들을 서로 다른 영역에 퍼뜨려라".
- **탐색 과제에서는 프런티어 주석을 뺀다.** 강한 방향 사전이 있을 때 프런티어 표시가 VLM을 경계 따라가기로 끌어 오히려 느려지기 때문(표 III).

### 믿음·불확실성

- **명시적 믿음(확률 분포)이 없다.** 관측 실패가 목표 확률을 깎는 갱신도 없다. 이미 본 영역은 점유 지도 이미지에서 free로 보일 뿐이다.
- 단서의 신뢰도·오류 가능성을 다루는 장치 없음. v1에는 이전 계획 요약·실행 요약을 다음 프롬프트에 넣는 기억 장치가 있었으나 v3 알고리즘에는 빠졌다.

### 시뮬레이션 설정

| 항목 | 값 |
|---|---|
| 지도 | **중앙 복도 + 양쪽에 무작위 크기 방**. 소 60×30, 중 120×60, 대 150×80 격자 |
| 로봇 수 | 소 2, 중 4, 대 6 |
| 센서 | 거리 10셀, 시야각 π/3, 가려짐 반영. 단위 속도, 저수준 A*, 다른 로봇은 반경 1 장애물 |
| 시행 | 규모별 지도 10개 × 초기 배치(및 물체 위치) 10개 = 규모·과제당 100회 |
| 재계획 주기 | 모든 방법 T_H = 50 스텝. GPT-4o max token 1024, temperature 0.2 |
| 기준선 | RACER(HGrid + 쌍별 CVRP + TSP), AEP + Dynamic Voronoi Cell |

### 주요 결과 (완료 스텝, 평균 ± 표준편차)

| 방법 | 탐사 소 | 탐사 중 | 탐사 대 | 탐색 소 | 탐색 중 | 탐색 대 |
|---|---|---|---|---|---|---|
| RACER | 181.25 ± 28.70 | 254.12 ± 26.52 | 368.02 ± 33.09 | 164.73 ± 35.87 | 244.73 ± 31.89 | 370.80 ± 43.05 |
| AEP+DVC | 171.81 ± 22.75 | 248.08 ± 23.65 | 359.85 ± 29.15 | 160.47 ± 30.93 | 244.45 ± 27.69 | 365.94 ± 37.11 |
| COMRES-VLM | 156.12 ± 25.29 | 212.23 ± 17.12 | 323.02 ± 19.17 | 63.21 ± 18.19 | 104.25 ± 19.15 | 162.24 ± 18.50 |

- 기준선은 탐색 시간이 탐사 시간과 거의 같다(사전 정보를 쓸 수 없어 사실상 전부 훑음). COMRES-VLM은 대형에서 탐색이 탐사의 약 절반. 초록의 "55.7 %"는 대형 탐색에서 AEP+DVC 대비 감소율(365.94 → 162.24)이다. 탐사 이득은 10.2 %(초록), 중형 최대 14.5 %.
- 고정 시나리오 10회 반복(표 II): 탐사 RACER 272.00, AEP+DVC 261.70, Ours 233.00 / 탐색 272.00, 254.60, **121.6** / 계획 1회 계산 시간 3.16 s, 0.23 s, **6.74 ± 4.01 s**.
- 입력 구성 절제(중형, 표 III):

| 구성 | 탐사 | 탐색 |
|---|---|---|
| 이미지만 | 253.64 ± 49.71 | 240.87 ± 39.02 |
| + 골격 | 244.84 ± 17.32 | 225.73 ± 21.51 |
| + 골격 + 언어 사전 | 243.05 ± 22.87 | **105.72 ± 16.14** |
| 전체(+ 프런티어) | **214.25 ± 16.33** | 185.68 ± 42.84 |

- 언어 사전 하나로 탐색 시간이 절반 이하(240.87 → 105.72). 반대로 프런티어를 같이 주면 탐색이 185.68로 나빠진다.

### 실물

- Unitree **Go2** + X500 쿼드로터, 둘 다 Livox Mid-360, Intel NUC. SLAM Toolbox + Nav2, Wi-Fi로 중앙 PC(i7, 32 GB)에 지도 전송, 재계획 20 s.
- "목표는 오른쪽 복도 깊은 곳" 사전으로 홀에서 시연. **정량 결과 없음**(영상만).

### v1 (LLM-MCoX)과의 차이

- v1은 프런티어를 샘플링해 U(g) = s(g) − λ·c(g)(정보 이득 − 최근접 로봇 거리)로 상위 K개를 고르고 문(doorway) 검출을 추가로 넣었다. 기준선은 Mean-shift-Greedy, Sample-Greedy, Sample-DVC. 이질적 팀(빠르고 근시 / 느리고 원시)과 동굴형 비정형 지도 실험이 있었다.
- v1 수치: 대형 6대 탐사 22.7 % 단축, 비정형 탐색에서 언어 사전 시 Mean-shift-Greedy 대비 30.5 % 수준의 스텝, 이질 팀 약 30 %·사전 포함 최대 50 % 단축. 단일 로봇에서도 언어 사전이 Sample-Greedy보다 39 % 빠름.
- v1 본문은 "피해자가 다른 사람의 위치를 대략 말해 주는 수색·구조"를 동기로 명시한다.

## 논문에 없는 것

- **확률적 믿음**: 단서 → 위치 분포 변환, 관측 실패 시 갱신, 시간에 따른 확산이 전혀 없다. 언어는 매번 같은 문장이 프롬프트에 들어갈 뿐이다.
- **목표 1개**. 여러 피해자, 남은 인원 수, "몇 명" 같은 개수 정보 없음.
- **틀린·오래된 단서** 실험 없음. 사전 문장이 어떻게 생성되는지(정답 위치에서 자동 생성인지, 사람이 썼는지) 불명확하고, 사전은 늘 맞는 것으로 보인다.
- **움직이는 대상** 없음(정적 물체).
- **mapped ≠ searched** 구분 없음: 같은 2D 센서가 지도와 탐지를 동시에 하므로 "관측됨 = 탐색됨"이다.
- 화자 기준 방향("제 오른쪽 20 m"), 거리 단서, 방 순번("세 번째 방"), 층 정보 없음. 실행 중 새 단서가 들어오는 경우 없음(초기 정보 1회).
- 학습형 가중치 없음(영점 VLM). 탐색 결과의 신뢰구간·통계 검정 없음. 실물은 정성 시연뿐.

## 우리 설계에 주는 영향

1. **겹치는 부분을 솔직히 인정해야 한다.** "복도 + 양쪽 방" 생성 지도, 2D 점유 격자, 프런티어, 대략적 언어 단서로 탐색 시간을 약 절반으로 줄인다는 결과(55.7 %)가 이미 있고, 실물도 **Go2**다. 우리 61 %라는 숫자 자체는 새롭지 않다. "언어 단서가 탐색을 빠르게 한다"를 기여로 내세우면 안 된다.
2. **차별점은 '언어 → 확률 지도 → 점수'의 명시성이다.** COMRES는 VLM이 직접 웨이포인트를 고르는 블랙박스다. 우리는 VLM은 번역만 하고, 믿음 갱신(미탐지 시 (1 − p_detect) 곱, 이동 확산)과 기대 피해자/시간 점수를 코드로 한다. 그래서 (a) 틀린 단서 비율, (b) 단서 나이, (c) 파서 크기(2B vs 8B)에 따른 성능을 분리해 측정할 수 있다. COMRES에는 이 세 축이 모두 없다.
3. **기준선으로 그대로 쓴다.** "VLM-as-planner": Qwen3-VL-8B에 지도 이미지 + 골격 + 로봇 위치 + 단서 원문을 주고 웨이포인트 JSON을 받는 방식(그림 3 프롬프트 재현, 탐색 시 프런티어 주석 제거). 같은 120개 건물에서 우리 파이프라인과 비교하고, 틀린 단서·오래된 단서 조건에서 어떻게 무너지는지 보인다. GPT-4o 결과를 8B로 재현하면 성능이 떨어질 수 있으니 공정성 문제는 "같은 로컬 모델"로 맞춘다고 명시한다.
4. **프런티어 주석이 탐색을 해친다는 관찰(표 III)**은 우리 쪽 근거가 된다: 단서가 있을 때 "가장 가까운/큰 프런티어"보다 "단서 질량이 많은 쪽"을 따라야 한다. 우리 점수(기대 피해자 / 시간^κ)가 이를 명시적으로 표현한다.
5. **골격(위상 골격)**은 우리 "복도를 따라 세 번째 방" 해석(복도 경로상 기대 위치)에 그대로 쓸 수 있다. Zhang–Suen 세선화는 구현이 간단하다.
6. 계획 1회 6.74 s(GPT-4o API) — 우리는 VLM을 단서당 1회만 부르고 목표 선택은 코드라 이 지연이 없다는 점도 실용적 차이로 적을 수 있다.
7. v1의 동기 문장("피해자가 다른 사람 위치를 말해 줌")은 우리 시나리오와 사실상 같다. 관련 연구에서 반드시 인용하고, 차이를 "여러 피해자, 틀림·노화, 확률 갱신, 카메라 탐지 ≠ 지도"로 정리한다.
