# HiPAN 상위 항법 설계 (시뮬레이션)

목표점을 주면 depth만 보고 자세를 바꿔 가며 그곳까지 가는 상위 정책.
HiPAN 논문 정리: [papers/hipan.md](papers/hipan.md). 목표점 선택기는 아직 구상 중이라 **지금은 목표점을 무작위로 준다.**

## 구조

```
목표점 g (지금은 무작위; 나중에 목표 선택기) → 몸 기준 상대 목표
[상위 정책] 10 Hz : (teacher) 특권 지도 / (student) D435i depth + GRU  → c = [vx, vy, ωz, 높이, roll]
[하위 student] 50 Hz : weights/go2_hipan_low_student.pt (고정), 제어 지연 0–20 ms
```

## 구현 위치

| 파일 | 내용 |
|---|---|
| `sim/go2_lab/nav_world.py` | 방 생성기, 특권 지도 계산, 시작/목표 및 경로 (numpy만 사용) |
| `sim/go2_lab/hipan_nav.py` | Isaac 환경 (`Go2-HiPAN-Nav`, `-Depth`), PGCL, 보상, 10 Hz 래퍼 `NavVecEnv`, PPO 설정 |
| `sim/go2_lab/hipan_nav_student.py` | depth + GRU student 네트워크 |
| `sim/scripts/train_hipan_nav.py` | teacher PPO (`--smoke N`: 동작 확인) |
| `sim/scripts/distill_hipan_nav.py` | student DAgger |
| `sim/scripts/eval_hipan_nav.py` | 학습에 안 쓴 지도에서 평가 |
| `sim/scripts/check_depth_overhead.py` | 머리 위 장애물이 depth에 보이는지 확인 |

## 환경

- 12×12 m 방 6×8개. 행이 높을수록 어려움 (난이도 0→1).
- 방 하나에 들어가는 것:
  - 바깥 벽
  - 칸막이벽 0–2개: 문 1–2개, 폭 0.9–1.6 m. 일부 문에는 **낮은 상인방**(일부는 기울어짐)
  - 탁자: 다리 4개 + 상판, 상판 높이 0.36–0.8 m
  - **떠 있는 보와 낮은 판**: 무너진 잔해. 아래 틈 0.32–0.66 m, 어려울수록 낮음. 기울기 최대 ±0.25 rad
  - 바닥 잡동사니
- 로봇 높이 기준 (XT16 꼭대기 = base + 0.163 m):
  - 서서 통과하려면 틈 ≥ 0.51 m
  - 최대로 낮추면 틈 ≥ 0.31 m에서 통과
- 과제: 큰 연결 영역 안에서 시작/목표 쌍을 방마다 64개 만듦. 경로 길이 2.5–15 m.
  - 기준 경로는 Dijkstra로 계산한다. 비용 = 장애물 근접 비용 + 낮춰야 하는 칸의 비용. HiPAN은 GVD 위 A*를 쓰지만 우리는 이것으로 대신한다.
- 바닥은 평지. 하위 student가 거친 지형 + 낮은 자세에서 약하기 때문.

## teacher 입력

| 그룹 | 내용 |
|---|---|
| `nav` (66) | 하위 student 관측 62 (직전 명령 c 포함) + 상대 (하위)목표 3 (yaw 좌표, 5 m에서 자름) + 원하는 속도 1 |
| `priv` (5) | 운동 상태 [v_B, 높이, roll] |
| `map` (2×41×31) | 로봇 주변 x −1~3 m, y ±1.5 m, 0.1 m 간격: **바닥 장애물 높이**와 **머리 위 여유 높이** |

HiPAN은 3D 점유 14×11×11과 2.5D 고도 31×21을 쓴다. 우리 장면은 상자만으로 이루어져 있어서, 같은 정보를 2D 두 채널로 정확히 표현했다. 높이 해상도가 0.1 m 격자보다 정밀하다.

## 행동

c를 [−1, 1]로 정규화한다. 각 성분의 범위:

| 성분 | 범위 |
|---|---|
| vx | −0.5 ~ 1.0 m/s |
| vy | ±0.4 m/s |
| ωz | ±1.2 rad/s |
| 높이 | 0.12 ~ 0.36 m |
| roll | ±0.5 rad |

하위 student는 roll 1.0을 따라가지 못하므로 roll 범위를 ±0.5로 좁혔다.

## 보상 (논문 Table IV 기반, 일부 수정)

| 항목 | 가중치 | 비고 |
|---|---|---|
| 도착 ((하위)목표 0.25 m 이내) | 5.0 | |
| 진행 (이전 거리 − 현재 거리, ±0.2 m로 자름) | 3.0 | **우리가 추가** |
| 상태 방문 0.5 m 칸, 1/√횟수 | 0.2 | 논문 0.5 |
| 속도 exp(−\|v_des − ‖v‖\|/0.3) | 0.25 | v_des는 에피소드마다 0.3–0.8 m/s 무작위 |
| 명령 변화 / 부드러움 | −0.1 / −0.1 | |
| 추종 오차 | −0.2 | ‖Δv‖ + 0.3\|Δωz\| + 5\|Δh\| + \|Δroll\| (우리가 정함) |
| 몸 속도 | −0.1 | vz² + 0.1‖ω_xy‖² (우리가 정함) |
| 기본 자세 | −0.04 | ((h−0.30)/0.1)² + (roll/0.3)² (우리가 정함) |
| 명령 한계 | −2.5 | |
| 충돌 (몸통·머리·다리) | −2.5 | |

- 종료 조건: 몸통이나 머리가 무언가에 닿음(XT16 포함), 목표 도착, 시간 초과. 시간 제한은 10 s + 3 s × 경로 길이(m).
- **목표 도착은 시간 초과처럼 처리한다(부트스트랩).** 방문·속도 보상이 매 스텝 양수라서, 도착을 진짜 종료로 두면 목표를 피하는 쪽이 이득이 된다. 논문에는 이 처리가 명시되어 있지 않다.
- **첫 학습 실패 (v0)**: 논문 가중치 그대로 쓰니 목표에 가지 않고 방문 보상만 모았다 (140회 반복에 성공 1.5 %, 행동 std 0.09로 붕괴). 진행 보상 추가, 방문 0.5→0.2, 초기 std 0.5→0.8, 엔트로피 0.005→0.01로 바꾼 뒤 정상 학습됨 (156회에 성공 71 %, 544회에 83 %).
- γ = 0.995. 10 Hz에서 0.99면 20–30 s 걸리는 목표가 거의 보이지 않는다.

## PGCL

- 기준 경로 위에 d m 간격으로 하위목표를 둔다. 처음 d = 1 m.
- 하위목표를 모두 지나 도착하면 d를 1 m 늘린다.
- d가 경로 길이보다 커지면 최종 목표만 준다.
- 최종 목표에 2번 연속 성공하거나 3번 연속 실패하면 새 과제를 받는다.

## student (DAgger)

- **입력**
  - depth 64×112: D435i 위치 (0.32, 0, 0.055) m, 아래로 13°, 87×58°. 4 m에서 자르고 [0, 1]로 정규화. Isaac 레이캐스트로 생성
  - `nav`
  - 하위 student가 추정한 운동 상태
  - 최종 목표만 줌
- **네트워크**: CNN + GRU(256) → c, 그리고 teacher 지도 잠재 z_s(256)의 추정값
- **손실**: ‖c−ĉ‖² + 0.1‖z_s−ẑ_s‖². 32스텝 단위로 잘라서 BPTT
- **우리 확장**: 에피소드 도중 목표가 바뀐다 (스텝마다 확률 0.003). 목표 선택기가 목표를 계속 바꾸는 상황에 대비하기 위함

## 머리 위 장애물이 depth에 보이는가

`results/hipan_nav/depth_overhead.{json,png}`

보 아래 높이 0.35 / 0.42 / 0.50 m, 렌즈에서 보 앞면까지 거리 0.3–3 m에서 확인했다.

| 몸 높이 | 결과 |
|---|---|
| 서 있음 (0.32 m, 카메라 0.38 m) | 모든 경우에 보이고, 화면의 10–40 %를 차지함 |
| 낮춤 (0.15 m, 카메라 0.21 m) | 1 m 이상 떨어져 있으면 모두 보임. 가까워지면 안 보임: 0.42 m 보는 0.3 m 이내, 0.50 m 보는 0.7 m 이내 |

결론: 다가가는 동안에는 보이므로 낮출지는 1–3 m 앞에서 정할 수 있다. 그 뒤 실제로 통과하는 동안에는 기억(GRU)에 의존한다. HiPAN도 같은 구조다.

### v2: 숙인 채로 계속 가는 문제

`scripts/posture_hipan_nav.py`: 특권 지도로 머리 위 여유 높이를 보고, 스텝마다 상황을 나눠 명령 높이를 집계했다.

| 상황 | v1 명령 높이 / 0.26 m 미만 비율 | v2 |
|---|---|---|
| 주변이 트임 | 0.285 m / **25 %** | 0.301 m / **10 %** |
| 앞에 장애물 | 0.293 / 19 % | 0.300 / 9 % |
| 장애물 아래 | 0.209 / 73 % | 0.233 / 56 % |
| 막 통과함 | 0.273 / 35 % | 0.288 / 18 % |

- 원인: 기본 자세 벌점(−0.04)이 너무 약해서 숙인 채 걸어도 손해가 거의 없었다.
- 수정 (`upright`, −0.3): 로봇 앞뒤 −0.4~1.0 m, 좌우 ±0.3 m의 머리 위 여유가 모두 0.6 m 이상이면 기본 높이(0.30 m)보다 낮은 만큼 제곱 벌점을 준다.
- v1 teacher에서 이어 1,000회 학습했다. v2 student 증류가 진행 중이다.

### 실로봇 depth와의 차이 ([실로봇 시험](real_test_20261126.md))

- D435i는 848×480(89.5×58.6°)으로 실행해야 시뮬레이션 카메라와 시야가 같다.
- 장착 기울기는 약 11.6°다 (설계값 13°).
- student 증류 때 추가할 것:
  - ±4° 자세 무작위화
  - 왼쪽 빈 띠와 테두리 빈 선 (빈 픽셀 → 4 m)
  - 픽셀 누락 약 5 %
  - 거리 제곱에 비례하는 노이즈
